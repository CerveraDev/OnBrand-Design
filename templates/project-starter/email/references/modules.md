# Modules

## Required Module: Hero

Every __PROJECT_NAME__ email must include a hero module.

Locked:

- __PROJECT_NAME__ logo placement or inclusion must respect the supplied source file or approved template.

Required:

- Headline
- Hero image

Optional:

- Subheading
- CTA inside or near hero

Layout variants:

1. Logo, headline, and hero image separated.
2. Logo above image, headline below image.
3. Logo and headline overlaid on hero image.
4. Logo, headline, and subheading overlaid on hero image.
5. Fully composited hero image with visual elements baked into one image.

## Hero Compatibility Rule

For cross-client compatibility, avoid fragile live overlays when the design depends on precise layering. Prefer a flattened hero image when the campaign requires complex visual compositing, such as a hard hat hovering above the building.

After the hero image is finalized, decide whether the headline should be:

- Live HTML text above or below the image
- Live HTML text in a simple compatible overlay
- Baked into the image

## Required Module: Footer

Every __PROJECT_NAME__ email must include a locked footer partial. See [footers.md](footers.md).

## Optional Modules

Provisional modules to refine later:

- Intro/body copy block
- CTA block
- Event details block
- Image gallery or recap block
- Amenity spotlight block
- Construction progress block
- Residence/floorplan spotlight block
- Broker information block

Add module rules only when a real campaign need appears.

Calibrated projects may also define optional locked static blocks and machine-readable header/hero compatibility. Static blocks have no editable slots, require explicit include/exclude decisions, and retain their approved copy and structure. A standalone header must not be combined with a hero that already includes one.
